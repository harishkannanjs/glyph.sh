## 0. ROLE

You are a senior full-stack engineer and technical platform architect. You are building, end to end, a production-ready personal technical blog for a security researcher / full-stack developer (reverse engineering, bug bounty research, low-level systems, robotics side projects), to be hosted on GitHub Pages.

You own the entire build: content pipeline, all page logic, all components' functional behavior, search indexing, RSS/sitemap/SEO, CI/CD, and deployment. You do **not** freehand the visual design — the UI is authoritative from `terminal-blog-ui-brief.md` (generated via Stitch) and from Stitch's own output. Where Stitch's generated UI and this prompt's functional requirements intersect, implement the functionality *inside* Stitch's UI shell rather than inventing new visual patterns.

Do not stop partway and hand back an incomplete or partially-wired project. The definition of done (§10) is the bar — do not consider this finished until every item in §10 is checked.

| Deployment | GitHub Actions → GitHub Pages (`actions/deploy-pages`); Pages source = GitHub Actions |
| Package manager | bun |
| Domain | Default `<username>.github.io` (no custom domain/CNAME) |

## 3. COMPLETE FEATURE CHECKLIST

Every item below must ship. Nothing here is optional or a "nice to have if time permits" — this is the full agreed scope across all tiers. Implement Tier 0 → Tier 1 → Tier 2 → Tier 3 in that order, but all four ship in the final product.

### Tier 0 — Foundation
- [ ] Drop a `.md`/`.mdx` file in `src/content/blog/` + `git push` → automatically appears on the index, gets its own route, appears on relevant tag pages, is included in `feed.xml` and the search index — zero manual wiring
- [ ] Individual post pages sharing one `<BlogPostLayout>` — no post defines its own page shell
- [ ] Reading time computed from actual word count (not hardcoded)
- [ ] Tags with filterable `/tags` and `/tags/[tag]` pages
- [ ] Syntax-highlighted code blocks with copy button
- [ ] Fully responsive, mobile through ultrawide, per UI brief §7 breakpoints
- [ ] RSS/Atom feed at `/feed.xml` (or `/rss.xml`)
- [ ] SEO: per-page title/description/OG/Twitter-card meta, canonical URLs, `sitemap.xml`
- [ ] 404 page in full site theme (per UI brief §6.6)
- [ ] Favicon + default social preview image
- [ ] Light/dark theme, dark as default, toggle persisted across visits (localStorage), per UI brief §5.1
- [ ] Pagefind-powered search
- [ ] GitHub Actions auto-deploy on push to `main`
- [ ] Draft support (`draft: true` hides from listing/RSS/search in production builds; confirm exclusion, not just hiding, per brief)
- [ ] Auto-generated TOC per post from headings, sticky rail ≥1280px / inline disclosure below that (UI brief §5.6)
- [ ] `Published` + optional `Updated` dates (Updated = frontmatter `updatedDate`)

### Tier 1 — Premium reading experience
- [ ] Sticky TOC with active-section highlighting as the reader scrolls
- [ ] Heading anchors with hover-visible `#`, click-to-copy deep link, "Copied" confirmation (UI brief §5.7)
- [ ] Sidenotes/margin notes on wide viewports (≥1400px), collapsing to numbered footnotes below that (UI brief §5.8)
- [ ] Code blocks with: language badge, copy button, optional line numbers, specific line-range highlighting, diff view (`+`/`-` gutter markers) (UI brief §5.5)
- [ ] Reading-progress bar, post pages only (UI brief §5.14)
- [ ] Command palette (`Ctrl+K` / `/`): search posts + tags, keyboard-navigable, opens from anywhere except while another text input is focused (UI brief §5.4)
- [ ] Astro View Transitions across navigation, shared-element morph from PostCard title → post page title; fully disabled under `prefers-reduced-motion`

### Tier 2 — Subject-specific
- [ ] Spoiler/reveal blocks (`<Spoiler>` MDX component) for CTF flags/exploit payloads/answers (UI brief §5.9)
- [ ] Mermaid diagram support via `<Mermaid>` MDX component for exploit chains, memory layouts, state machines
- [ ] KaTeX math rendering for crypto/algorithm/SMT-style content
- [ ] Embedded asciinema terminal recordings via `<Asciinema>` MDX component
- [ ] Series grouping as a first-class concept: `series`, `seriesPart`, `seriesTotal` frontmatter fields; series strip on post pages showing progress dots and a link to the full part list (UI brief §5.10); series must not be implemented as a bare tag

### Tier 3 — Trust & polish
- [ ] Auto-generated OG image per post at build time (e.g. via `astro-og-canvas` or a Satori-based build script) — no manual image creation required per post
- [ ] Changelog popover next to the `Updated` date: compact revision list + optional expandable full diff, reusing the code-block diff styling (UI brief §5.15)
- [ ] Copy-as-Markdown button on post pages, same interaction pattern as the code-block copy button (UI brief §5.16)
- [ ] Related posts by shared tags, end of post, before comments (UI brief §5.11)
- [ ] Prev/Next post navigation, omitting whichever side doesn't apply (UI brief §5.12)
- [ ] giscus discussion section, theme-synced (UI brief §5.13)

## 4. CONTENT & FRONTMATTER SCHEMA

Define in `src/content/config.ts` with Zod, so the build fails loudly (not silently) on missing/invalid required fields:

```yaml
---
title: "Post Title"
description: "One-line summary for SEO/cards"
pubDate: 2026-09-13
updatedDate: 2026-09-20          # optional
tags: ["reverse-engineering", "windows-internals"]
draft: false                      # optional, default false
heroImage: "/images/posts/slug/cover.png"   # optional
series: "Windows Internals"       # optional
seriesPart: 2                     # required if `series` is set
seriesTotal: 4                    # required if `series` is set
changelog:                        # optional, powers the changelog popover (§3 Tier 3)
  - date: 2026-09-20
    summary: "Corrected the offset calculation in the PTE example"
	    diff: "..."                   # optional raw diff text/markdown
		---
		```

			`author` is fixed to a single constant (site config, not per-post frontmatter) since this is a solo blog.

			Validate: if `series` is set, `seriesPart`/`seriesTotal` must also be set (and vice versa) — enforce with a Zod `.refine()`, not a silent default.
